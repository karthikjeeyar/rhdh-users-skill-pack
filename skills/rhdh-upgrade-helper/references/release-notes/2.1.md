# RHDH 2.1 Release Notes

Red Hat Developer Hub 2.1 is generally available. It is a fully supported, enterprise-grade productized version of upstream Backstage 1.54.9 and uses Node.js 24.21.0 and CLI 2.1.2.

Sources: [RHDH 2.1 release notes](https://docs.redhat.com/en/documentation/red_hat_developer_hub/2.1/whats_new-red_hat_developer_hub_release_notes) and [RHDH 2.1 migration guide](https://docs.redhat.com/en/documentation/red_hat_developer_hub/2.1/migrate-migrate_from_rhdh_1_x_to_2_1).

This curated file focuses on upgrade-relevant facts verified for the `rhdh-upgrade-helper`. Consult the linked release notes for the complete feature, known-issue, and advisory lists.

## New features and enhancements

- **RHDH 2.1 is generally available** with Backstage 1.54.9, Node.js 24.21.0, and CLI 2.1.2.
- **New Frontend System is generally available and the default**: All Red Hat-owned and supported frontend plugins are migrated to NFS, and plugin and module exports move from the `/alpha` entry point to the main entry point.
- **Supported and community plugins are available as OCI artifacts**: Supported plugins come from `registry.access.redhat.com`; community plugins come from `ghcr.io`. Bundled plugin wrappers under `./dynamic-plugins/dist/` are removed.
- **`ref://` references default catalog plugins**: `ref://<plugin-name>` resolves by plugin name and is preferred over `{{inherit}}`. Keep `{{inherit}}` only when the package URL includes a `!plugin-path` suffix.
- **The `enabled` setting controls dynamic plugin loading**: Use `enabled: true` or `enabled: false`. If both `enabled` and `disabled` are present, `enabled` takes precedence.
- **Homepage frontend and backend plugins are generally available**: The frontend plugin is renamed from `dynamic-home-page` to `homepage`; the backend plugin is enabled by default.
- **The Operator supports OLM v1** on OpenShift Container Platform 4.18 and later. The Operator catalog uses File-Based Catalog images. The OLM v0 path remains available for earlier OpenShift versions.
- **The Helm chart can deploy a StatefulSet**: Set `workload.kind` to `StatefulSet`. The default remains `Deployment`.
- **Helm supports an in-place upgrade from 1.y to 2.1** after the values are migrated; uninstalling the existing release is not required.
- **Default network policies protect workloads**: The Operator and Helm chart create default-deny `NetworkPolicy` resources plus rules for known traffic flows. The cluster network plugin must enforce `NetworkPolicy`, or the resources have no effect.
- **Corporate proxy support uses Node.js built-in proxy handling**: Set `NODE_USE_ENV_PROXY=1` on the backend along with `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY`.
- **Supported PostgreSQL versions are 15 through 18**: PostgreSQL 14 is no longer supported. The default local database image is PostgreSQL 18.
- **The sign-in page discovers configured authentication providers**: RHDH no longer defaults to GitHub or Guest when a provider is missing or misconfigured. The deprecated `signInPage` setting still overrides automatic discovery.
- **RBAC-aware UI visibility**: Sidebar links and entity tabs are hidden when the user lacks the required permission.
- **Dynamic plugins can be defined inline in the Backstage custom resource**, using the same configuration format as the ConfigMap-based approach.
- **NFS frontend plugins support Backstage feature flags**, configurable per user under Settings > Feature Flags.
- **Intelligent Assistant enhancements**: Screen context awareness (opt-in), saved custom prompts, organization-specific knowledge sources, and configuration entirely through Lightspeed Core. The assistant can use the Offline Knowledge Portal for RHDH documentation.
- **MCP server authentication and controls**: Bearer token and OIDC authentication, per-user permission checks, action filters, and audit logging.
- **Frontend loading and HTTP/2**: Dynamic frontend plugins load earlier and reuse more shared dependencies. HTTP/2 can be enabled through a supported reverse proxy.
- **Additional generally available capabilities**: Bulk Import, Signals frontend, must-gather, frontend Kubernetes plugin, and the homepage backend plugin.
- **Backstage UI adoption**: RHDH 2.1 applies Red Hat product styling to Backstage UI components, and selected plugins now use Backstage UI instead of Material UI.
- **Orchestrator improvements**: Workflow access through conditional policies with `IS_ALLOWED_WORKFLOW_ID`, inline form validation, nested workflow inputs, improved run troubleshooting, and Go template substitution in flavor configurations.

## Technology Preview features

- **The Scorecard plugin moves from Developer Preview to Technology Preview**.
- **Scorecard threshold enforcement**: Platform engineers can use `scorecard.entityAnnotations.thresholds` to prevent users from changing specific thresholds or all thresholds.
- **Scorecard advanced aggregation types**: Scalar aggregations `SUM`, `AVERAGE`, `COUNT`, `MAX`, and `MIN` support roll-up KPIs across applications and components.
- **Scorecard DORA metrics**: Deployment Frequency, Lead Time for Changes, Change Failure Rate, and Time to Restore Service.
- **Scorecard SonarQube module**: Integrates SonarQube Cloud or private SonarQube data, including quality gate status, security ratings, security hotspots, coverage, maintainability, and reliability.
- **The GitLab events module moves from Developer Preview to Technology Preview**.

## Developer Preview features

- **MCP Registry entity provider**: Adds MCP server API entities from any MCP Registry that follows the official registry specification.
- **OpenShift AI connector updates**: Sidecar containers are removed, `AiModelServerAPI` replaces the previous entity kinds, KServe `LLMInferenceService` support is added, and model discovery and agent support are introduced.
- **RHDH on ARM64 clusters**: Supported as a Developer Preview with community images from `quay.io/rhdh-community`. Productized multi-architecture images are not included, and the Intelligent Assistant is not validated on ARM64 and should be disabled.
- **AI-assisted software template authoring**: A community skill helps AI coding agents scaffold, validate, and discover software templates.
- **`AiResource` entity kind**: Register AI skills and rules from Git repositories or OCI images and discover them through catalog search and the Intelligent Assistant.
- **`rhdh-cli` organizational knowledge graph commands**: Intent-based commands list, get, validate, register, and unregister catalog entities; retrieve API specifications; search catalog, TechDocs, and templates; and run software templates.
- **Agent Skills for the Intelligent Assistant**: Platform engineers can configure organization-specific instructions and reference material that the assistant selects for relevant prompts.
- **`DevHubPluginCatalog` custom resource**: Manage plugin catalogs as namespace-scoped Kubernetes resources and merge multiple catalogs into a `default-config` ConfigMap.
- **Operator reconciliation for plugin configuration**: Set `OPERATOR_DP_PROCESSING=true` to validate plugins during reconciliation, expose plugin status, and enable automatic rewriting of plugin and catalog image references for disconnected environments.

## Deprecated features

- **The generic `fast` OLM channel is deprecated**: New 2.y releases are published only to versioned `fast-X.Y` channels, such as `fast-2.1`. Subscriptions on `fast` remain on the last 1.y release.
- **Skipping minor or major versions is not supported**: Starting with 2.1, the Operator narrows `skipRange` to require the previous minor version. You must be on 1.10.z to upgrade to 2.1 and on 2.1.z to upgrade to 2.2.
- **The `SIGUSR2` heap dump collection method is deprecated**: Use the default `inspector` method.
- **The `signInPage` frontend configuration is deprecated**: Configure providers under `auth.providers` instead. The setting remains available as an override, and the dynamic plugin `signInPage` override remains available.
- **The Azure Container Registry plugin moves to Community support**: Use its `oci://ghcr.io` reference to continue using it.
- **Material UI v4 is deprecated for plugins**: Migrate to Backstage UI, or to MUI v5 where no Backstage UI equivalent exists.
- **Some partner-owned plugins move to Community support** instead of generally available support.
- **The `disabled` setting for dynamic plugins is deprecated**: Use `enabled` instead. The setting still works and is scheduled for removal in RHDH 2.3.
- **Orchestrator per-workflow permission strings are deprecated**: Replace `orchestrator.workflow.<workflow_id>` and `orchestrator.workflow.use.<workflow_id>` with conditional policies that use the `IS_ALLOWED_WORKFLOW_ID` rule. There is no automatic migration.
- **The Ping Identity plugin moves to Community support**: For supported Ping Identity authentication, use the PingFederate authentication provider.

## Removed features

The following are breaking changes in RHDH 2.1.

- **Scorecard provider configuration moves to `scorecard.metricProviders`**: Update `scorecard.plugins` to `scorecard.metricProviders`. Provider IDs use `<datasource>.<providerName>`. The Filecheck provider uses `filecheck.fileExistence`, with file configuration under `options`. Threshold annotations use the full metric ID `scorecard.io/<metricId>.thresholds.rules.<key>`.
- **Scorecard aggregation cards must use `app.extensions`**: Previous Scorecard card mount points in `dynamic-plugins.yaml` no longer work. Configure aggregation cards in `app-config.yaml` through `app.extensions`, or set the aggregation ID on a customizable homepage card.
- **TechDocs custom MkDocs plugins must be allowlisted**: Only a built-in set is permitted. Add trusted plugins to `techdocs.generator.mkdocs.dangerouslyAllowAdditionalPlugins` or `techdocs.generator.mkdocs.defaultPlugins`.
- **The `dynamic-home-page` plugin is renamed to `homepage`**: Update `dynamic-plugins.yaml` entries that use the old name.
- **The default local database image changes from PostgreSQL 15 to PostgreSQL 18**: PostgreSQL 15 remains supported. An existing PostgreSQL 15 data directory is incompatible with the PostgreSQL 18 image, so migrate the data or pin a supported PostgreSQL 15 image before upgrading.
- **RHDH container images are rebased on Red Hat Enterprise Linux 10** instead of the previous RHEL base version.
- **Plugin wrappers for Technology Preview plugins are removed**: `dynamic-plugins.default.yaml` references some of these plugins from `oci://ghcr.io`.
- **The New Frontend System is the default and the Old Frontend System is removed**: Remove `APP_CONFIG_app_packageName=app-next` and `ENABLE_STANDARD_MODULE_FEDERATION=true`. Migrate custom frontend plugins to NFS and move frontend wiring from `dynamicPlugins.frontend` to `app.extensions` and `app.routes.bindings`.
- **Authentication providers are no longer shipped statically**: Install each provider as a dynamic plugin and configure it under `auth.providers.<id>`. Guest login is not enabled automatically in development; install and configure the Guest plugin explicitly. `disableIdentityResolution` is removed; omit `signIn.resolvers` for auxiliary providers.
- **Plugin wrappers for generally available plugins are removed**: `dynamic-plugins.default.yaml` references some of these plugins from `oci://ghcr.io`.
- **The Global Floating Action Button plugin is removed**: Remove its entry and use the Global Header plugin for quick actions and shortcuts.
- **The Helm chart values are restructured**: The new structure is not backward compatible. Migrate the values before upgrading an existing Helm release.
- **Intelligent Assistant permission sets are feature-based**: Replace CRUD-based permissions with `intelligent-assistant.chat`, `intelligent-assistant.notebooks`, `intelligent-assistant.mcp.tools`, and `intelligent-assistant.skills`, using the `use` action.
- **The Plugin Certification Program is removed**: Certification badges are removed from Extensions Catalog metadata, and the `extensions.backstage.io/certified-by` annotation is no longer needed.
- **Developer Lightspeed is renamed to the Red Hat Developer Hub intelligent assistant**: Configuration keys and values that reference `lightspeed` are renamed to `intelligent-assistant`. The route is now `/intelligent-assistant`; existing `/lightspeed` links redirect.
- **Scorecard metric IDs use `lowerCamelCase`**: Update all Scorecard metric IDs from `snake_case` to `lowerCamelCase`.
- **app-config ConfigMaps must contain exactly one data entry**: Multi-entry app-config ConfigMaps break after this update. Split each into separate single-entry ConfigMap resources, including the default ConfigMap and those referenced by the custom resource.
- **The Ping Identity catalog backend module plugin is removed**: `@backstage-community/plugin-catalog-backend-module-pingidentity` is no longer in the supported or Technology Preview catalogs. Use the PingFederate authentication provider for supported Ping Identity authentication.
- **The 1.10 RAG content image is no longer shipped**: `quay.io/rhdh/rhdh-rag-content-rhel9:1.10` is replaced by the `lightspeed-stack` sidecar for the intelligent assistant.
- **OAuth sign-in no longer uses unverified emails**: If an identity provider marks an email as unverified, RHDH does not use it for identity resolution. This does not affect dedicated OIDC providers such as Keycloak or Red Hat build of Keycloak.

## Known issues

- **Styles on other pages can render incorrectly after visiting Docs or a TechDocs entity tab** (RHDHBUGS-4055): Reload the browser after leaving Docs or TechDocs to restore correct styles.
- **Bulk import repository picker search does not match organization names** (RHDHBUGS-4017): Search by repository name or page through the repository list.
- **Bulk import reports success when a pull request cannot be created** (RHDHBUGS-4016): Check each imported repository for its pull request, remove catalog locations without a pull request, and retry those imports.
- **The Catalog page does not show the new empty state** (RHDHBUGS-3948): Other entity-based pages show the new empty state.
- **The Backstage default not found page is shown instead of the RHDH page** (RHDHBUGS-3947): This affects missing pages and pages the user cannot access.
- **Duplicate plugin configurations can prevent RHDH startup** (RHDHBUGS-3928): When the Intelligent Assistant or Orchestrator is enabled, adding plugins already provided by the feature can cause a `Duplicate OCI plugin configuration` error. For Helm, customize `intelligentAssistant.plugins` or `orchestrator.plugins` and remove matching `dynamicPlugins.plugins` entries. For the Operator with `OPERATOR_DP_PROCESSING=false`, customize existing `ref://` entries instead of adding equivalent `oci://` entries.
- **The Report an issue link is not visible on TechDocs pages in NFS** (RHDHBUGS-3664): Enable the add-on with `app.extensions: [- addon:techdocs/report-issue: true]`.
- **Possible slower response time with a large number of plugins** (RHDHBUGS-4077): Users might see slower UI and API responses and increased memory consumption. Core functionality remains unaffected.

## Fixed issues (upgrade-relevant)

- **The Helm chart selects the correct PostgreSQL password secret key for custom usernames** (RHDHBUGS-3689): The chart now selects the correct secret key when `postgresql.auth.username` is not `postgres`.
- **Orchestrator database creation Job is renamed and fails correctly on errors** (RHDHBUGS-2577): The Job is renamed from `<release>-create-sonataflow-database` to `<release>-create-sf-db-<version>`. The old Job remains on the cluster after upgrade and can be deleted manually.
- **Dynamic plugin installation no longer delays pod termination** (RHDHBUGS-3463): The init container forwards `SIGTERM` to child processes, reducing shutdown time during plugin installation.
- **GitHub SAML SSO token expiration no longer causes a 403 error** (RHDHBUGS-3216): Workflows can add a SAML SSO check step that prompts for re-authentication.
- **Repository publishing actions no longer fail behind DPI proxies** (RHDHBUGS-3148): Pushes fall back to the GitHub GraphQL API when binary Git smart protocol packets are rejected.
- **The OwnedEntityPicker field no longer fails with HTTP 431** (RHDHBUGS-2522): This affected users in many groups with long names and multiple `catalogFilter` entries.
- **Catalog search visibility matches catalog browsing for `HAS_LABEL` and `HAS_ANNOTATION` policies** (RHDHBUGS-3011): Label and annotation keys and values are evaluated case-insensitively.
- **An empty `spec.flavours` array now disables all default flavors** (RHDHBUGS-3198): Omit the field to use the default flavors.
